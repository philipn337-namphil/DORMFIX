# Security design and implementation boundary

Foundation behavior: only GET /actuator/health/liveness and /actuator/health/readiness are anonymous. All business traffic is denied, HTTP Basic/form login/default generated users are disabled, and no token is issued or accepted. This is fail-closed scaffolding, not completed authentication. CSRF is disabled only for this stateless, cookie-free boundary. No CORS origins are enabled by default.

Phase 1 design: use Spring Security's supported JWT/resource-server primitives for Bearer access validation, explicit issuer/audience/algorithm allow-list, expiry/not-before, bounded clock skew and rotating asymmetric keys. Do not write a bespoke JWT parser or infer roles from unverified claims. Access lifetime and suspension/revocation behavior need a security contract; long-lived stale role claims cannot substitute for current worker/owner/scope checks.

Password storage uses Spring PasswordEncoder (adaptive salted BCrypt or reviewed Argon2 configuration), with cost benchmarked on the deployment hardware. Never plaintext/reversible passwords, logs of login payloads or user-selectable privileged signup roles. Exact signup eligibility/role provisioning is to be approved in Phase 1; do not import old context as a new frozen rule. Return generic login failures, rate-limit auth attempts at a measured boundary, and test account status checks.

Refresh/logout design is proposed in ADR-013: rotating opaque refresh tokens, server-side hashes, expiry/reuse detection, revocable token families and logout invalidation. The frozen ERD has no refresh store. No table, Redis or fake successful refresh/logout is added before approval. If browser refresh cookies are chosen, use HttpOnly/Secure/SameSite and restore endpoint-specific CSRF protection; same-origin deployment is preferred. Access tokens should not be placed in URLs. Token storage/transport and residual access-token validity after logout must be explicit.

Enforcement layers:

1. Security filter authenticates and supplies trusted actor identity, rejects invalid/missing credentials with 401.
2. Application use case checks roles plus reporter ownership, current active assignment or administrator dormitory scope; deny with 403 before running forbidden commands. Query projections apply the same resource scope and visibility.
3. Domain methods reject invalid lifecycle states/invariants with 409. SUPER_ADMIN receives no state bypass. Worker assignment checks run in the command transaction to avoid stale authorization.

No mass assignment from entity binding. Metadata DTO allow-lists exclude forbidden fields. Bean Validation covers inputs; application/domain code covers relationships and state. Errors never include SQL, stack traces, password values or signing details. Resident query paths must filter STAFF_ONLY comments and reviewed private history metadata, including lists/counts, not just UI rendering. Former workers cannot mutate through comments/WorkLogs/attachments/visit endpoints. Multi-role semantics and staff scope remain approval questions.

S3: private bucket, block public access, encryption, TLS-only policy, least-privilege prefix-scoped EC2 role, no access keys in env files. Authorize before presigning and again before registering/downloading. Generate unpredictable server-owned object keys bound to request/uploader; never trust arbitrary keys/paths from clients. Allow-list file types, validate actual signature/content where applicable, and enforce configured size limits both before presign and after upload (HEAD/content verification outside DB transaction). Presigned PUT alone is not a trustworthy size/type guarantee. Validate declared metadata, existence and ownership; prevent replay/overwrite via unique object key and reviewed registration policy. URLs expire quickly and must not be logged. Exact limits, scanning/quarantine and orphan cleanup lifecycle are deferred to attachment slice review; no unlimited upload default.

CORS uses explicit reviewed origins/methods/headers; never wildcard with credentials. Prefer Nginx same-origin. Production HTTPS, trusted proxy headers only, private RDS with verify-full TLS, separate migration/runtime identities, EC2 IAM role and Secrets Manager/SSM SecureString. Local .env is ignored. Production secrets live outside checkout with restrictive permissions; CI uses OIDC/short-lived credentials in a later approved CD phase. Logs exclude passwords/tokens/consent/private messages/presigned URLs. Dependency updates and vulnerability review precede real deployment.
