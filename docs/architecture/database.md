# Database and JPA conventions

PostgreSQL 17 is the initial local/test family, with a pinned 17.6 image for reproducibility. Review patched versions and supported RDS versions before deployment. Flyway is the only schema authority; Hibernate ddl-auto=validate and open-in-view=false in every runtime profile. Phase 0 V1__foundation.sql is deliberately SELECT 1, exercising migration history without preempting unresolved product DDL. Testcontainers validates real PostgreSQL startup/migration. No H2 substitution.

Physical mapping conventions (ADRs 002/007): snake_case tables/columns, User -> app_user to avoid a reserved identifier, BIGINT identity IDs (GENERATED BY DEFAULT AS IDENTITY) using JPA GenerationType.IDENTITY. IDs are internal and unrelated to request_number; request-number generation format is unresolved. Do not change logical ERD fields. Prefer explicit tables/columns/index names in migrations and mappings.

Persist enums as strings with @Enumerated(STRING), VARCHAR plus named CHECK constraint, never ordinals. ENUM in the frozen ERD is logical; new/removal/rename values require a reviewed migration and compatibility analysis. Enum width/nullability not stated in the ERD must be reviewed with the slice rather than assumed. JSONB belongs to RequestHistory metadata; avoid arbitrary entity dumping and PII.

Use Instant for TIMESTAMPTZ; UTC JDBC setting; ISO-8601 transport with offsets. Use LocalDate for Residence/installation dates, with Dormitory timezone for business date interpretation. Auditing uses a testable Clock and application-side timestamp assignment at creation/update; preserve immutable created_at. @PrePersist/@PreUpdate may implement the convention, but bulk SQL bypasses callbacks and must explicitly handle timestamps/versioning. No speculative audited base entity shared by every aggregate.

Equality: entities default to object identity unless real collection/use-case needs ID equality. If overriding, compare non-null persistent IDs only, handle Hibernate proxies, use stable class-based hashCode; never use mutable fields, associations or generated-ID hash changes. Value objects use value equality. Never Lombok @Data, public status setters or toString traversing associations.

Prefer scalar IDs across aggregates. If an association is justified, explicitly LAZY, unidirectional by default, no cascade across independent aggregates, no uncontrolled CascadeType.ALL or orphanRemoval. Map to response DTOs/projections within query transactions. Controllers receive no entities or persistent collections. Resolve N+1 with explicit fetch joins/entity graphs/projections tailored to endpoints; measure SQL when adding lists. Do not paginate a collection fetch join. Bound page size (engineering default 20, max 100 until endpoint review) and stable sort including ID; avoid unbounded findAll.

MaintenanceRequest requires @Version Long version. API compares supplied version, Hibernate protects flush-time races. Critical assignment constraint: unique(request_id) WHERE unassigned_at IS NULL. Mandatory access indexes are listed in the [ERD](../product/erd-v1.md). Test real PostgreSQL uniqueness/rollback/concurrent commands when adding the assignment slice. Residence non-overlap cannot be reduced to end_date IS NULL without resolving date semantics; ROOM validation and concurrency must be addressed in that slice.

Every production schema change has an immutable V<number>__description.sql migration. Start business migrations at V2. Branches coordinate migration numbers during PR rebase; never renumber an applied shared migration. Local and CI migrate from empty DB; future tests also cover upgrades from previous release. Never use baseline-on-migrate to hide drift, Flyway repair to bypass failures, or clean on shared databases. Validate checksums before deployment. Migration application requires a dedicated DDL identity; runtime identity has only required DML and no schema ownership.

Use expand/contract, bounded backfills, lock/statement timeouts, compatibility checks and backups before risky changes. No down migrations as routine rollback. Removing constraints/columns or altering frozen relationships needs approved ADR and human review. Do not casually hard-delete operational/history data. DB-level restrictive foreign keys should reinforce preservation after delete actions are reviewed. Append-only data gets no update/delete methods in ordinary repositories; production grants may additionally restrict it.
