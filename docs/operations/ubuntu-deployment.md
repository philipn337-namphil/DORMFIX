# Ubuntu deployment runbook (future execution only)

No real server/resources were created by foundation. Execute only after explicit deployment authorization and architecture/security acceptance. This is a checklist/template, not a deploy script. Single-host deployment may interrupt traffic.

1. Select supported Ubuntu LTS and RDS PostgreSQL versions; establish staging before production. Provision approved VPC/subnets/security groups/IAM with cost review outside this phase. RDS is private; EC2 app port is loopback-only; S3 is private. Verify SSM or restricted SSH recovery access.
2. Install patched Docker Engine/Compose and Nginx from supported package sources. Enable Docker at boot, verify non-root app image, host firewall and disk/log rotation. Operator docker-group access is effectively privileged and should be limited. Apply OS hardening/patch/reboot policy.
3. Put reviewed checkout/templates at /opt/dormfix. Create /etc/dormfix, secret-backed app.env (0600) and current RDS CA certificate at /etc/dormfix/rds-ca.pem. Validate DB_URL uses verify-full with the mounted certificate. Runtime DB user has required DML only; DDL role is separate. Do not place credentials in shell history or Git.
4. Build/test image in CI, retain digest and scan result. Operator creates /etc/dormfix/release.env containing DORMFIX_IMAGE=registry/repository@sha256:... (no mutable latest). Authenticate registry using short-lived IAM where applicable. Pull selected digest before startup.
5. Back up/verify PITR and rehearse restore in staging. Run Flyway validate then migrate once using that release's migration files and a compatible pinned migration runner, DDL identity and reviewed lock/timeouts. Capture resulting schema version. Exact runner command is a CD-phase prerequisite; do not improvise a latest tool or run repair/clean. Production app profile disables automatic migrations.
6. Replace REPLACE_DOMAIN/certificate paths in infra/nginx/dormfix.conf.template. Install infra/nginx/log-format.conf within http {} before the site. Obtain TLS certificate and configure automated renewal (the redirect-only template assumes certificate bootstrap already handled). Verify nginx -t, then reload. Test renewal, HTTPS and forwarded-header trust. Enable HSTS only after HTTPS/subdomain policy is confirmed.
7. Validate production Compose with operator release env and env file present using config --quiet. Copy systemd unit to the appropriate system directory, daemon-reload and enable --now dormfix only when authorized. Unit uses /opt/dormfix and /etc/dormfix/release.env; Docker must be enabled. This is future host configuration, not performed now.
8. Verify docker compose ps, container non-root/read-only settings, localhost liveness/readiness, HTTPS endpoint behavior and unauthorized API behavior. Nginx blocks external actuator access; use local probe/operator path. Test the first implemented feature's smoke contract once it exists.
9. Configure CloudWatch collection/retention/alarms, backup alerts, certificate expiry alerts and runbook ownership. Reboot staging and verify Docker/systemd recovery. An unhealthy container does not automatically restart solely due to health status; alert and investigate.
10. Record image digest, migration version, release time, probes and recovery evidence. Human accepts staging results before protected production promotion. See [rollback](rollback.md).

No production DNS names, regions, ARNs, credentials or cloud resources are supplied. Template validation does not prove production readiness; TLS/IAM/RDS/migration/restore checks require the actual approved environment.
